# GBP / Local SEO / Schema Audit — 2026-07-12

Scope: full `app/**/page.tsx` sweep (86 pages) against the mandatory GBP/local-SEO
checklist (NAP consistency, schema coverage, CTAs, reviews, FAQ, content freshness).
Parallel AI MCP tools were not connected in this environment (not in the active
server catalog), so this audit used direct codebase inspection + built-in web
search/fetch instead.

## 🔴 Fixed: NAP visible-text mismatch (real bug, not a second office)

Six landing pages had a sticky bottom CTA block where the `tel:` link correctly
pointed to `7025001064`, but the **visible button labels** showed two different,
undocumented numbers — `(702) 500-1955` for "CALL NOW" and `(702) 222-1964` for
"TEXT" — while the paragraph directly above the buttons, on the same page, said
"Call 702-500-1064 or text 702-500-1064." This is a straight NAP-consistency
violation of the always-on rule ("visible text and schema must match GBP exactly"):
the *href* matched, but the *label* didn't.

This is a single-office site (Dr. Janet Duffy Real Estate, 1180 N Town Center Dr,
Las Vegas, NV 89144) — there is no second office or dedicated-line rationale for
`(702) 500-1955` / `(702) 222-1964` anywhere in the codebase, schema, or docs.
`app/layout.tsx` explicitly documents the one dedicated line and warns: *"NEVER
replace with 702-222-1964."* Git history shows the six landing pages were added in
a commit literally titled "...Revert to single phone number 702-500-1064..." — the
button labels were just never updated to match. Confirmed as a copy/paste artifact,
not an intentional unique-office number.

**Fixed** — labels now read `CALL NOW: (702) 500-1064` / `TEXT: (702) 500-1064` to
match the `tel:` target, the LocalBusiness schema (`SCHEMA_PHONE`), and every other
NAP instance on the site (header, footer, NAPSection, contact page, condo/neighborhood
pages).

Files: `app/summerlin-real-estate-agent/page.tsx`, `app/sell-house-fast-las-vegas/page.tsx`,
`app/sell-my-house-fast-summerlin/page.tsx`, `app/relist-home-las-vegas/page.tsx`,
`app/home-wont-sell-las-vegas/page.tsx`, `app/find-new-real-estate-agent-las-vegas/page.tsx`.

## 🔴 Fixed: 11 pages missing BreadcrumbSchema

The always-on rule requires LocalBusiness/schema consistency site-wide. A prior
audit (Nov 2025, see `AUDIT-SUMMARY.md`) flagged the same gap; it had been closed
for all condo/neighborhood pages but these 11 utility/content pages still had no
`BreadcrumbSchema`:

`app/30-day-plan`, `app/case-studies`, `app/contact`, `app/market-analysis`,
`app/marketing-strategy`, `app/privacy-policy`, `app/resources`, `app/results`,
`app/selling-tips`, `app/terms`, `app/why-choose-me`.

**Fixed** — added the standard `<BreadcrumbSchema items={[...]} />` (Home → Page)
using the same pattern already used across the rest of the site. Verified with
`scripts/audit-pages.mjs` (added to the repo — re-run any time with
`node scripts/audit-pages.mjs`): all 86 `page.tsx` files now report `breadcrumb=Y`.
